# PRD — 网文创作数据 Dashboard

本地个人 Web 工具，把网文创作草稿（异构 Markdown）解析→可视化 Dashboard，并提供界面更新数据的能力。

> 版本：1.0（草案） · 状态：Phase 2+（运维/实战排错强化） · 适用环境：dev / test / prod（三套独立本地库）
> 关联文档：[DESIGN-webnovel-dashboard.md](DESIGN-webnovel-dashboard.md) · [ui-mockup/index.html](ui-mockup/index.html)

---

## 1. 背景与目标

### 1.1 背景
用户正在创作一部长篇网络小说（家族·重生·金融题材）。创作素材存放在 `Design_Folder/` 下，以**异构、半结构化的 Markdown** 组织，包括人物档案、银行/股票台账、各国收益测算表、汇率、时间线、逐资产计算文件等。这些素材是小说设定的"数据底座"，需要精确、一致、可追溯。

### 1.2 现状痛点

| # | 痛点 | 具体表现 |
|---|------|---------|
| 1 | **数据不可视** | 人物档案、时间线、财务数值都是静态文本，看不出"家族财富随时间怎么变""各国投资收益曲线""人物关系图谱" |
| 2 | **查找靠人肉** | 想查"1990 年代家族做过什么""某年某资产收益多少"，要在多个 markdown 间来回翻 |
| 3 | **更新靠手改文件** | 增改时间线事件、人物字段、某年收益都要直接改 markdown/CSV，格式敏感、易错 |
| 4 | **数据健康不可见** | 跨文件一致性（时间线对齐、金额一致）有没有矛盾，没有汇总视图 |

### 1.3 产品目标
做一个**本地个人 Web 工具**，把创作草稿解析后以 **Dashboard 可视化**，并提供界面更新数据的能力。

### 1.4 核心约束（不可妥协）
- **源 markdown 是只读输入**：`Design_Folder/`（Novel 设计源库）**绝不回写**。
- 界面更新**不直写数据库**，通过独立的「用户数据 md 覆盖层」承载。
- 数据更新走**文件导入**（数据调整员放文件 + 代码级解析），而非 UI 逐格编辑（仅时间线/编年史除外）。

## 2. 边界声明

### 2.1 范围内
- 解析 Design_Folder 各类 markdown → 归一化入本地 Postgres → Dashboard 可视化。
- 统一搜索、健康校验、日历游标（按截至所选日历日年-月-日重建数据；源数据缺粒度按规则补全）。
- 两人角色流：数据调整员放文件导入；前端 UI 用户查看/决策。
- 文件模型：新增文件导入 / 更新文件 diff + 回退（含磁盘复原）。
- 仅导出（markdown / CSV / 报告 PDF），不回写源。

### 2.2 非目标（v1）
- 不做多用户 / 鉴权 / 云部署。
- 不做 UI 初始化向导（初始化在代码/配置级完成）。
- 不做环境间数据迁移/同步（Phase 2 视使用情况）。
- 不提供源 markdown 的任意编辑能力（仅时间线/编年史可在 UI 编辑）。
- 不做实时计算财富曲线（用预计算逐年快照）。
- 统一搜索**不做 UI 向导类复杂交互**，但功能本体经**本地 LLM + embedding（RAG）** 纳入 **Phase 1**（见 P1-5、DESIGN §18）；不依赖云端，无鉴权本地推理。

### 2.3 术语
- **源数据 / 源 md**：`Design_Folder/` 下的创作者文件（Novel 设计源库）。
- **输入文件夹**：数据调整员放置待导入文件的目录（dashboard 的数据输入源；回退时应用可覆盖写回）。与 Novel 设计源库区分。
- **用户数据 md 覆盖层**：UI 可编辑内容的持久层（当前限于时间线/编年史）。
- **Postgres 派生索引库**：由「源 md + 覆盖层」合并、解析、归一化后的持久化索引，供可视化/检索/校验。
- **固定值类 / 年标记类**：数据两种形态（见 §6.3）。
- **基础数据导入范围（按阶段）**：`Design_Folder/` 下**除 `基准/事件/` 外的全部**为**基础数据**，Phase 1 导入归一化入 DB（无异常、可按日历游标重建收入/支出）。`基准/事件/`（电影/股票等事件素材）**Phase 1 排除**、Phase 1 完全不进系统；**Phase 2 重新纳入**，由数据调整员代码级导入后、UI 用户按同币种手动关联账户（见 §6.8）。
- **总资产构成**：`总资产 = 银行账户余额(现金) + 投资专款池(在途) + 股票持仓市值`。现金只进账户 `ledger`；持仓市值独立呈现在财富图谱、不并入账户余额；`买入股票 = 账户支出「购入股票」，现金移除`，故现金与市值不重叠（见 §6.9）。
- **收益挂账 & 账务本币**：收益文件（惠民租房/经营性房产/祖产股票债券/祖父开店）与薪资等，**逐年现金流按属地模块挂到对应人物/公司账户、以本币进本国货币池 `ledger`**；文件已写死金额/税后/币种，系统直接取数入账不重算；**账务始终本币、不折算 USD**，仅展示层家族总资产才折算 USD 现值（见 §6.10）。

## 3. 数据源清单（异构 Markdown）

> 以下为**结构模版**（数据格式示意），描述工具须解析的各类文件长什么样、提供哪些可抽取维度。示例中数值仅表意，不代表真实设定。（时间线.md 仅作为一种**代表性格式**的模板，本 PRD 不罗列其具体年份内容。）

| 类别 | 路径 | 结构模版 | 可抽取维度 |
|------|------|----------|-----------|
| 银行台账 | `经济/银行/*.md` | 按币种分节（`## 一、BEF（祖父）`…），流水表 `日期\|理由\|收入\|支出\|余额\|备注`，余额随行累计 | 账户 × 币种、逐期收支、累计余额 → **财富时间序列** |
| 股票台账 | `经济/股票/*.md` | `### 基本信息` 列表 + `### 年度明细` 事件表 `日期\|代码\|事件\|股数\|单价(USD)\|金额(万美金)\|持股比例\|备注` | 持仓事件、拆股/换股/收购链、累计持有 |
| 收益测算表 | `基准/收益表/*测算表.md` | 年度 × R1–R5 分级年化收益率表（多国版本） | 各国、各风险级、各年收益率曲线 |
| 汇率 | `基准/汇率/*.md` | `1EUR=40.3399BEF` 式对照 | 货币对、折算率；含年份→逐年表，无年份→**基准折算率**（常量，不随时间变） |
| 人物 | `人物/*.md` | `- 字段：值` 自由列表，含关系/日期 | 人物属性、角色关系、身份 |
| 时间线 | `时间线.md` | 按 decade 事件表 `年份\|事件\|备注`（仅作格式模版） | 年化大事、编年史条目 |

> **阶段项**：`基准/事件/*.md`（电影/股票等事件素材）**Phase 1 排除、不导入**；**Phase 2 重新纳入**（见 §2.3 按阶段导入范围与 §6.8/§6.9）。Phase 1 基础数据不含任何"事件"现金流（银行台账与事件文件结构性隔离、永不重叠，避免 double-count）。
| 收益测算表 | `基准/收益表/*测算表.md` | 年度 × R1–R5 分级年化收益率表（多国版本） | 各国、各风险级、各年收益率曲线 |
| 汇率 | `基准/汇率/*.md` | `1EUR=40.3399BEF` 式对照 | 货币对、折算率；含年份→逐年表，无年份→**基准折算率**（常量，不随时间变） |
| 人物 | `人物/*.md` | `- 字段：值` 自由列表，含关系/日期 | 人物属性、角色关系、身份 |
| 时间线 | `时间线.md` | 按 decade 事件表 `年份\|事件\|备注`（仅作格式模版） | 年化大事、编年史条目 |

**Phase 1 数据溯源对象**（建档→收益→入账，见 §6.10）：
- `基准/初始资产/*.md`（四长辈初始资本/面值/股票债券/房产 → `initial_asset` 存量建档）
- `基准/薪资/*.md`（养父母薪资 → 逐年现金流挂其账户）
- `基准/1974-2001家庭支出.md`（→ 挂 Henri Peeters 账户 支出；2002 起停设）
- `基准/CPI工资.md`（折算/展示基准参数）

**核心难点**：异构解析层 + 固定/年标记二分 + 多币种归一化 + 逐年快照重建。

## 4. 角色与权限

没有鉴权，但有两类**使用者视角**，产品的界面与数据流按此区分。

| 角色 | 谁能做 | 主要行为 | 更新权限 |
|------|--------|---------|---------|
| **前端 UI 用户** | 查看者 | 看 Dashboard、拖全局日历、收全局重算提示、查看健康校验、查看文件 diff 并决策；在公司图谱屏点按钮触发外部 API 导入（API①）；在投资界面产生派生投资数据 | 仅**时间线/编年史**（经用户数据 md 覆盖层）、**投资派生数据**（UI 第三类，见 §6.7）；对已更新文件选「更新/回退」 |
| **数据调整员** | 数据维护者 | 维护激活清单 `Design_Folder/import_files.yaml`（prod 严格白名单，`active:true` 才入库；dev/test 不读清单、全量导入）→ 把文件放进输入文件夹 → 代码级解析（看能否识别）→ 导入 DB → 让 UI 用户核对 | 通过文件导入维护**其余一切数据** |

**权限映射**
- UI 用户：只读查看 + 拖日历 + 收提示 + 时间线/编年史编辑 + **投资派生数据**（UI 第三类）+ 文件 diff 决策。
- 数据调整员：文件放置 + 代码级导入 + 健康校验 + 查看导入结果。

**写数据通道约束（对齐 §1.4 铁律）**：除**时间线/编年史**（经覆盖层）、**投资派生数据**（UI 第三类，§6.7）与**文件 diff 决策**外，所有涉及 `entity / finance_entry / ledger_entry / holding_event` 等行数据的写操作，**一律走文件导入或外部 API importer 内部逻辑**，不暴露为普通 UI 可直接调用的 CRUD；若 API 层仍提供这些写端点，仅作为 importer / 数据调整员的受限通道（DESIGN §14 中标注），普通 UI 用户不可直接调用。
- **例外说明**：投资功能是 UI 用户**第三类**可编辑内容——它产生的 `finance_entry`（派生投资收益）与专款池走账由 UI 直接触发，**不受上述"普通 UI 不可写 finance_entry"限制**；但必须经服务层校验（金额≤as-of余额、起始年下限、年度幂等），见 §6.7 与 DESIGN 投资节。

## 5. 环境

| 环境 | Postgres 库 | 数据来源 | 用途 |
|------|------------|---------|------|
| **dev** | 独立库 | 真实数据 | 联调开发 |
| **test** | 独立库 | 真实数据（测试可用子集，如：一个文件 30 条取 2 条） | 验证 |
| **prod** | 独立库 | 真实数据 | 日常使用 |

- 三环境为**三个互相独立**的本地 Postgres 库，同一套代码通过配置切换。
- **prod 导入门控（Phase 2+）**：生产库由 `Design_Folder/import_files.yaml` 激活清单严格白名单控制——仅 `active:true` 的源文件被导入；dev/test 不读清单、维持全量导入现状。新增源文件需先在清单登记并激活；可随时 `reset --env prod` 清空重建（不可逆）。启动前后端用 `Design_Folder/start_dashboard.sh`（`APP_ENV=prod`，后端 8001 / 前端 5173；仅启服务）。
- 环境间迁移 / 同步需求：**列入 Phase 2**，视 Phase 1 实际使用情况决定是否实现。
- 初始化在**代码/配置级**完成（读入数据目录、建库、首次解析），**不做 UI 向导**。

## 6. 功能需求

### 6.1 角色·数据调整员
- **F-A1 文件放置与激活**：把文件放入指定的输入文件夹（如 `基准/事件/*.md`）；生产环境另需在 `Design_Folder/import_files.yaml` 把该文件置 `active:true`（严格白名单：`active:true` 才入库；dev/test 不读清单、全量导入）。
- **F-A2 代码级解析识别**：在 ETL 运行时识别该文件、能否解析（模版可能略微不同）→ 给出"可导入 / 需人工处理"。
- **F-A3 导入 DB**：识别通过即导入 Postgres，触发重算。
- **F-A4 健康校验**：(与 UI 用户共用) 查看解析后的一致性校验结果。
- **F-A5 导入结果查看**：查看导入了哪些文件、解析行数、异常项。

### 6.2 角色·前端 UI 用户
- **F-U1 只读查看**：Dashboard 各屏可视化数据。
- **F-U2 日历游标**：日历控件选择到**年-月-日** → 按「截至该日」重建资产/财务状态；源数据缺粒度按 §6.3 默认规则补全到日。
- **F-U3 全局重算提示**：数据变更触发派生数据（全局）重算时，非阻断提示，可查看影响范围。
- **F-U4 健康视图**：查看一致性校验结果与问题清单。
- **F-U5 时间线/编年史编辑**：整理编年史（写入用户数据 md 覆盖层）。
- **F-U6 文件 diff 决策**：数据调整员更新了已存在文件时，看到旧/新版本 diff，并选择「更新数据源」或「返回上个版本」。
- **F-U7 公司外部导入触发**：在公司图谱屏点「获取/导入」按钮触发外部 API① 拉取公司基础信息（详见 §6.6）。

### 6.3 数据形态（贯穿全部功能）
- **固定值类**：不分年份的常量（初始资产、出资额、分成比例…）——常驻，与年份无关。
- **年标记类**：按某一年（或日期）生效的变更序列（逐年现金流、逐年模拟、流水行）——随日历游标累计。
- 日历重建口径：`截至某年 的状态 = 固定值常量 + 累计到该年的所有年标记变更`。
- **全局日历游标**：日历游标为**全 App 级常驻**（顶部固定），非仅 Dashboard；拖动后在所有 人物/公司/财务/曲线 等屏统一生效，以「截至所选日期节点」观看各实体/维度状态。
- **日期（统一日历年，无"财年/时间尺"）**：全系统用**日历历法（1/1–12/31，结算 12-30）**；源数据若为"某财年(6-30 截止)"须**归一为日历年日期**，不留财年维。全局日历可精确到**年-月-日**，源数据只给到年或年月时按**默认规则补全**：仅年份→当年 `12-30`（注明「年初」→`01-01`）；年份+月份→该月**月底**（写明「月初」→该月 `1 日`）；「上旬/中旬/下旬」→`1 日/11 日/21 日`。源数据超出规则无法判定时→**提醒并补充规则**（见 §10）。

### 6.5 文件变更模型（新增 / 更新）
| 场景 | 触发 | 决策权 | 流程 |
|------|------|--------|------|
| **新增文件** | 数据调整员放新文件 | 数据调整员 | 代码级解析能否识别 → 导入 DB → 增量重算 + 提示 |
| **更新已存在文件** | 检测到旧版本被改 | **前端 UI 用户** | 展示 diff（旧 vs 新）→ 择「更新数据源」或「返回上个版本」 |

**回退语义**：选择「返回上个版本」= **Postgres 保持上一版，且把输入/服务器文件夹里的磁盘文件也覆盖复原为上一版内容**（应用可覆盖写回输入文件夹；Novel 设计源库不受影响）。

### 6.6 公司与用工成本外部系统（P1）
公司与用工成本依赖**一个外部系统**，通过 **2 个独立 API** 对接（接口细节开发时定）：
- **API① 公司基础信息**：拉取公司权威信息 → 公司图谱。公司集合**只增不减**（图谱不删除已存在公司）；每个公司带状态字段 `status`（取值开发时定）。
- **API② 用工成本计算**：把本地**逐年「用工成本 + 税率」基准**（`基准/公司/用工成本/*.md`、`基准/公司/用工成本/税率/*.md`）作为输入发给外部 → 外部返回**当年各公司用工成本支出** → 导入，落到各公司下的**支出**（财务收支，挂公司实体）。
- **触发**：UI 用户可在公司图谱屏点击「获取/导入」按钮发起（API①）；API② 结果回导入后触发增量重算。

### 6.7 投资功能（P1 · UI 第三类派生数据）

投资是 UI 用户**第三类**可编辑内容（前两类：时间线/编年史、文件 diff 决策），产生**派生数据**：进 Postgres 派生层、债券编年史 view 可见，**绝不回写源 md**。

**操作流程**：选择 年份 → 地区 → 多选人物/公司 → 各主体按币种输入金额（或选「全部」=该主体所有币种账户一次全投）→ 选择 R1–R5 → 提交。

**地区=5 份测算表**：欧洲(1947 起)/英国(1983)/美国(1989)/香港(1999)/中国(2002)，各金入 `return_curve`；选地区即取该表当年 R 级年化，**不细分国家**。

**关键规则**（与 DESIGN 投资节一致）：
- **每「年份+地区」一年一次**；已投年份 UI 置灰不可重投；要改 → **解锁整笔抹除重输**，提交原子覆盖该年并触发向后重算。
- **计息**：按投资发生日(年月日)起 `当年 R ÷365 × 持仓天数`，天数 = 该年 12-30 − 发生日；当日投(12-30)收益=0。R 可为负（收益可能亏损，公式通吃正负）。
- **赎回**：每年 12-30 本金+收益划回银行、专款池清空；**次年不自动续投**（可换地区/R/金额或趴活期 2%）。
- **活期**：未投资金留银行账户、默认 2% 年化按日折。
- **余额上限**：各主体投入 ≤ 该主体 as-of 账户余额；account `全部` 取 as-of。
- **重算传播**：向后最小传播；固定金额冻结不追溯；仅「全部」与 as-of 变更后传。若前序改动致后年「全部」超限 → **整体拒绝该改动**（保守挡停，不做自动压缩）。
- **校验（服务层）**：金额≤as-of 余额(422)、地区起始年下限(422)、每地区年度幂等(409)——UI 派生通道补瘦版 hard-block。

### 6.8 UI 可改数据操作（全清单）

UI 用户可**直接改数据**的操作固化为四类（其余一切走文件导入 / 受限通道，见 §4 写数据通道约束）：

| # | 操作 | 改什么 | 前提/校验 | 记年 |
|---|---|---|---|---|
| 1 | 时间线/编年史 | 条目 | overlay | 条目年 |
| 2 | **投资**（§6.7） | 派生收益 | 金额≤as-of、R≥起始年、年度幂等 | 输入年份 |
| 3 | **事件→账户关联**（Phase 2，§6.9） | 挂账 | **同币种才连、不换算**；不符则不可关联 | 事件年 |
| 4 | **划拨 / 换汇**（Phase 1） | 币种转移 | 划拨=同币种；换汇需**输入年份有汇率**，缺则拦+按需导入;转出年起向后全链 as-of 不得为负，拐负则整体拒绝 | 输入年份 |

四类共享同一模板：落在「账户/资金池 × 年份」+ 向后重算传播 + 失败整体拒绝(选 i) + 同步编年史(overlay) + 服务层校验（瘦版 hard-block）。

### 6.9 事件·股票与资产模型（Phase 2）

`基准/事件/股票/**`（含收购、分拆、并购链）Phase 2 重新纳入导入；数据调整员代码级导入**不关联账户**，UI 用户按**同币种**手动关联到某账户（人物/公司）。其资产建模：

- **买入**：账户支出「购入股票」，现金移除 → 新建持仓批次(batch)。
- **分红**：每股派息×加权平均持仓 → 现金收入进账户（不并入持仓市值）。
- **卖出/减持**：现金收入进账户，**FIFO 从最早批次扣成本**，盈亏=卖出现金−批次成本，进账户。
- **分拆**（HPQ→HP+HPE）：成本按比分摊到新批次；现金不动。
- **换股+现金并购**（MVL→DIS）：换股部分成本随链(MVL成本→DIS批次)；现金部分进余额单独核算。
- **纯现金并购**（Perspecta→Veritas）：持仓归 0、现金进余额、**不记盈亏**。
- **成本 = FIFO**（每次买入=batch，各自成本）；用途=仅卖出结算盈亏，不参与总资产。
- **总资产构成**：银行账户余额(现金) + 投资专款池 + 股票持仓市值，见 §2.3。
- 归 **Phase 2**；Phase 1 的 wealth 曲线只含现金+投资池（无事件股票市值）。

### 6.10 Phase 1 摄入：数据流因果链与收益挂账

**摄入为一条因果链，非并列表**：`初始资产(存量) → 收益计算(逐年现金流) → 进入银行(账户活期)`，同一对象只有一份存量档案，不重叠。

- **ingest 顺序锁死**：`人物/` 先入 `entity` → 初始资产 → 收益文件(@entity_id) → 银行。收益模块挂 `entity_id` 依赖人物先导入。
- **归属主体 = 人物档案 `entity`**；收益模块按**属地/地域颗粒**拆分各挂各主体；归属名 ↔ `entity.name` **失配进 ingest_report 标需人工**。
- **收益文件 = 模块化**（一个文件多个属地子模块）；**股票债券按地域颗粒打包挂一个主体、包内收益分开算**；房产(A/B/C) 全算收益（经营性房产 + 惠民租房）；家庭主古堡也计收益。
- **薪资/收益文件已写死金额/税后/币种**：系统**直接取数入账、不重算税率/CPI/人口分段**（文件即权威）。
- **起始现金进余额**：初始资产里的**现金 = 直接进对应账户银行作为初始余额**，是"钱→收益/投资"的本金种子。
- **薪资/收益各归各主体**：养父薪资→养父账户、养母薪资→养母账户；收益各进各主体；**家庭支出统一记 Henri 账户**（故事设定）。
- **投资手动推进**：钱→收益测算表投资(R1–R5)→年末赎回分红进银行→**次年需用户手动重投**（非自动续投），可改地区/R/金额或转投股票/电影(Phase2)。
- **支出**：家庭支出取"年度总支出"行挂 **Henri Peeters 账户**支出；**2002 起家庭支出设定停止**。
- **币种生命周期**：BEF/LUF/NLG **2002-01-01 关池**（只读终态、历史可回溯），EUR 池开**承接分录**（原币/金额/折算汇率）；收益文件已内置 EUR。

## 7. 文件变更模型（详）

### 7.1 新增文件
1. 数据调整员把新文件放入输入文件夹。
2. 触发代码级 ETL：按类别匹配模板 → 尝试解析。
3. 解析识别（可能需轻微适配不标准模板）→ 成功 → **导入前冲突检测**（DESIGN §11.4）：
   - 无冲突 → 导入 DB → 增量重算 → 前端提示 UI 用户。
   - 有冲突 → **该文件不入库**，进 `ingest_report` 精确列出冲突点（文件/行/规则/新旧值），由**数据调整员**在文件侧解决后重导。
4. 失败：标记"需人工处理"，列出识别失败原因。

### 7.2 更新已有文件
1. 系统保留每个文件**上一版完整内容**（版本基准）。
2. 检测到文件变更 → 用旧基准 + 新内容做 **diff**。
3. 前端把 diff 展示给 **UI 用户**。
4. UI 用户二选一：
   - **更新数据源**：采纳新版本 → 重新解析导入 → 增量重算 + 提示。
   - **返回上个版本**：Postgres 保持上一版，且把磁盘文件覆盖复原为上一版内容。

### 7.3 回退语义（确认）
「返回上个版本」= **DB 保持上一版 + 磁盘文件复原为上一版内容**。应用对输入文件夹有覆盖写回权限；Novel 设计源库（`Design_Folder/`）永不写。

## 10. 解析与换算策略（要点）

> 完整算法见 [DESIGN](DESIGN-webnovel-dashboard.md)。

- **固定/年标记判定**：常量（出资额、分成比例、初始资产）→ 固定值；逐年/日期行 → 年标记。
- **多币种归一化**：按 `exchange_rate` 逐年折算；同比币种分组、异币种分开核算。
- **R1–R5 映射**：收益测算表按国家 × 风险级 × 年份建立基准。
- **复利/杠杆口径**：按收益率 × 杠杆倍率（如 2 倍）滚动；口径自洽校验。
- **余额连续校验**：`后一余额 = 前一余额 + 收入 − 支出`，不一致即报健康问题。
- **逐年快照预计算**：按固定值 + 累计年标记，预生成每年 as-of 快照。
- **日期默认规则**：仅年份→当年 `12-30`（注明年初→`01-01`）；年份+月份→该月**月底**（写明月初→该月 `1 日`）；「上/中/下旬」→`1 日/11 日/21 日`。源数据**超出规则、无法判定**时→**提醒并补充规则**（持久化 `date_rule`，供后续解析复用）。
- **增量重算起点**：变更的「受影响起算年」（如某电影首笔影响 1995 年）起向后重算，**不全量**。

## 11. 健康校验规则（清单）

- **时间线对齐**：时间线事件日期 vs 台账/收益表年份一致。
- **金额一致**：跨文件同一标的金额一致（如台账与收益表）。
- **汇率链自洽**：`A→B→C` 折算回 `A→C` 闭合。
- **复利/杠杆自洽**：按口径重算与前值相符。
- **断链检测**：关系/引用指向不存在的实体。
- 结果：汇总视图 + 问题清单（文件/行/规则/建议），供两角色查看。
